# Profile menu and photo

Tap the top-right avatar, then **Add profile photo** (or **Change profile photo**). Choose a JPEG, PNG or WebP image. The square preview saves immediately; **Done** closes the editor. **Remove photo** restores your initial. The dropdown also provides Settings and Sign out. Keyboard users can open it with Enter or arrow keys, move with arrows/Home/End and dismiss with Escape or Tab. Outside taps dismiss it.

No database migration, Auth configuration change, new environment variable or dependency is required. The implementation reuses the existing private `inventory-photos` bucket, authenticated photo proxy and verified Supabase session. Deploy the code using the existing Vercel project. Existing inventory, financial records, account passwords and beta authorizations are unchanged.

Private photos are stored under the verified user's UUID with a generated `profile-<uuid>.jpg` filename. Only the reference is saved in the user's Supabase Auth metadata (`thrift_log_avatar`); other metadata is preserved. Metadata never grants access or supplies the account identity. Uploads/removals check same-origin requests, fresh Auth and beta access, and derive the account from the session. The private image proxy checks current access and the owned path on every request; no public or bearer image URL is issued. A different or revoked user cannot read the photo. Private photo bytes are not saved to localStorage or the service worker.

Images are resized and center-cropped to at most 512px square in the browser, then decoded and normalized again on the server; EXIF/location metadata is stripped. Server uploads have a bounded 5 MB body/file limit plus multipart overhead and reject corrupt, oversized or animated images. The picker accepts original images up to the existing image preparer's 20 MB / 40 megapixel limits and uploads a much smaller JPEG. HEIC files must be exported as JPEG first. A failed upload keeps the previous photo. After a confirmed replacement/removal, cleanup only deletes the previous validated profile image when no inventory item references it; cleanup uncertainty leaves private bytes intact. A lost Auth-save response reports uncertainty and retains bytes for safe recovery.

The verified server page identity includes the profile reference, so it persists across reloads/devices without another profile metadata request during tab navigation. Image failures fall back to the email initial. The demo instead saves a bounded, normalized JPEG in its own browser-only key; resetting the demo removes it and never changes private accounts.

Regression coverage includes actual image decoding, invalid/cross-account requests, revoked access, failed writes, inventory-photo protection, keyboard/focus behavior, 320/390/430px layouts, private upload/replace/remove/reload and a second browser context sharing only the signed-in session. Auth/storage integration tests use isolated loopback service doubles and synthetic images. Physical iPhone Safari/PWA photo-library testing remains manual.
